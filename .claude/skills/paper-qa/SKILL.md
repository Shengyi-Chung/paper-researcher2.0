# query-holder

## Role

A specialized conversational Skill that manages follow-up interactions between users and previously retrieved paper data.

Acts as a lightweight conversational research workspace built on top of outputs generated by upstream Skills such as:

- `paper-search`
- `paper-analyze`
- `paper-report-generator`

This Skill is responsible for:

- contextual follow-up understanding
- multi-turn query resolution
- paper comparison
- local knowledge retrieval
- lightweight reasoning
- optional web augmentation

without modifying the global agent workflow.

---

# Core Capabilities

## 1. Multi-turn Context Tracking

Maintains conversation state across turns:

- currently discussed papers
- recent comparisons
- active keywords
- previously selected papers
- recent user intent

Supports reference resolution such as:

| User Query | Resolved Meaning |
|---|---|
| "what dataset does it use?" | resolve "it" from previous paper |
| "compare it with the second paper" | resolve both references |
| "which one is more novel?" | resolve previous comparison pair |

---

## 2. Conversational Retrieval

Supports:

- paper detail lookup
- keyword filtering
- author search
- benchmark retrieval
- contribution-based retrieval
- method-based retrieval
- comparison queries

---

## 3. Lightweight Reasoning

Provides lightweight synthesis over retrieved papers:

- identify differences
- summarize strengths/weaknesses
- rank novelty
- infer common trends
- compare methodologies

without performing heavy autonomous planning.

---

## 4. Local + Web Hybrid Retrieval

Primary retrieval source:

```text
/data/
```

If local information is insufficient:

- optionally trigger web search
- search GitHub repositories
- search PapersWithCode
- retrieve author pages
- retrieve citation/follow-up information

Web augmentation is only used when necessary.

Primary source:

```text

```

Contains:

```json

  "analysis_date": "...",
  "query": "...",
  "ranked_papers": [...]
}
```

Each paper may contain:

- title
- arxiv_id
- authors
- abstract
- relevance_score
- key_contributions
- methods
- datasets
- metrics
- novelty_score
- github_url
- benchmark_results

---



```json

  "active_keywords": [],
  "recent_queries": [],

  "last_query_type": ""

```

# Query Types

---

## Type 1: Paper Detail Query

### Trigger

- "tell me more about ..."
- "details of ..."
- "what does this paper do?"

### Action

Retrieve detailed paper information.

### Supports

- fuzzy title matching
- contextual paper reference resolution

---

## Type 2: Keyword Filter Query

### Trigger

- "papers related to ..."
- "methods involving ..."
- "papers about uncertainty"

### Action

Filter papers using:

- title
- abstract
- methods
- contributions
- datasets
- benchmark tags

---

## Type 3: Comparison Query

### Trigger

- "compare A and B"
- "difference between ..."
- "which one is better?"

### Action

Generate structured comparison.

### Comparison Dimensions

| Aspect | Description |
|---|---|
| Task | research objective |
| Method | core approach |
| Architecture | backbone/model |
| Dataset | evaluation datasets |
| Benchmark | quantitative results |
| Novelty | methodological contribution |
| Efficiency | runtime/model size |
| Strengths | advantages |
| Weaknesses | limitations |

---

## Type 4: Author Search Query

### Trigger

- "find papers by ..."
- "other works from ..."
- "papers written by ..."

### Action

Search local papers first.

If insufficient:

- optionally perform web augmentation.

---

## Type 5: Benchmark Query

### Trigger

- "which paper performs best on ..."
- "papers evaluated on Breakfast"
- "methods using F1@50"

### Action

Search benchmark metadata.

---

## Type 6: Conversational Follow-up Query

### Trigger

- "what about the baseline?"
- "does it outperform prior work?"
- "which one is more efficient?"

### Action

Resolve references from conversation state.

# Workflow

---

## Step 1: Load Conversation State

Load:

```text
/data/query_session.json
```

Restore:

- active papers
- comparison state
- active keywords
- recent interactions

---

## Step 2: Parse User Query

Extract:

- paper titles
- authors
- datasets
- methods
- benchmark names
- comparison targets
- pronoun references

---

## Step 3: Intent Classification

Supported intents:

| Intent | Description |
|---|---|
| paper_detail | detailed paper lookup |
| keyword_filter | thematic retrieval |
| comparison | compare papers |
| author_search | retrieve author papers |
| benchmark_query | dataset/metric lookup |
| followup_reference | contextual follow-up |

---

## Step 4: Reference Resolution

Resolve:

- it
- this paper
- the second one
- that method

using:

- recent focus papers
- comparison history
- dialogue state

---

## Step 5: Retrieve Matching Papers

Retrieval sources:

1. local structured data
2. intermediate artifacts
3. optional web augmentation

Retrieval techniques:

- fuzzy title matching
- keyword matching
- contribution matching
- method matching
- benchmark matching

---

## Step 6: Lightweight Reasoning

Perform:

- difference summarization
- trend synthesis
- novelty ranking
- contribution comparison
- benchmark comparison

---

## Step 7: Generate Response

Format:

```text
Query: ...
Matched Papers: ...

[contextual answer]
```

---

## Step 8: Update Session State

Update:

- active papers
- recent comparisons
- active keywords
- selected papers

Persist to:

```text
/data/query_session.json
```

The Skill should maintain lightweight memory only.

Should persist:

- current papers
- recent comparisons
- selected report papers
- active topics

Should NOT persist:

- full long-term history
- unrelated user information

## RESTRICTIONS (严格限制)

### ✅ 本 Skill 必须做的：
1. **管理对话状态** - 跟踪当前讨论的论文、比较对、关键词
2. **解析用户查询** - 识别论文标题、作者、数据集、方法、引用
3. **检索本地数据** - 从 `/data/paper_analysis.json` 和 `/data/papers.json` 查询
4. **轻量级推理** - 总结差异、比较方法、排名创新性
5. **引用消解** - 解析 "it"、"this paper"、"second one" 等指代

### ❌ 本 Skill 禁止做的：
1. **禁止搜索论文** - 不调用 arXiv API（由 paper-search 处理）
2. **禁止分析论文** - 不评分、不提取贡献（由 paper-analyze 处理）
3. **禁止生成完整报告** - 不生成 Markdown 报告（由 paper-report-generator 处理）
4. **禁止生成研究简报** - 不生成 briefing 格式（由 briefing-report-generator 处理）
5. **禁止修改全局工作流** - 不改变数据层文件内容
6. **禁止执行重量级规划** - 不进行自主规划和复杂推理
7. **禁止持久化长期历史** - 仅保持当前会话状态
8. **禁止主动网络搜索** - 仅在本地数据不足时可选触发

### 📌 边界情况：
- 如果用户请求完整报告 → 拒绝，告知使用 paper-report-generator
- 如果用户请求搜索新论文 → 拒绝，告知使用 paper-search
- 如果用户请求简报 → 拒绝，告知使用 briefing-report-generator
- 如果用户请求分析 → 拒绝，告知使用 paper-analyze
